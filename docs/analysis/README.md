这三份文档是 P0 镜头 IR 改造的设计依据，按阅读顺序排列。它们是决策记录，不是使用文档；代码以 `apps/web/src/novelcut/` 为准。

| 文件 | 内容 | 结论用途 |
|---|---|---|
| `novelcut-深读笔记.md` | NovelCut 源码深读：七阶段管线、分层降维、快照与覆盖率、帧型正负约束、图像内容寻址缓存、批量重试 | 确定可复用模式与必须替换的缺陷（零测试、localStorage 上限、.docx 不支持、全串行） |

| `颗粒度可行性与改造建议报告.md` | 31 类逐条可行性评级、主流管线颗粒度对照、四层数据模型、逐文件改造建议、P0–P3 路线 | 直接落地为 P0 的 `ShotIR` + `TrackClip` + `RenderPlan` 三层结构 |

## 关键判断

1. **分层降维是长链条 AI 管线的技术前提**：下游只读上一层产物，上下文大小恒定，成本线性可预测。
2. **31 类适合做标签和检查清单，不适合做 31 种平铺生产对象**：主流是“分镜宽表 + 独立素材轨 + 处理预设”。`ShotIR`（宽表）→ `TrackClip`（素材）→ `RenderPlan`（派生时码）三层与之对应。
3. **时码必须相对镜头派生**，绝对时码只存在于 `RenderPlan`；否则改一个镜头时长会让后续全部颗粒失效。
4. **转场跨两个 shot**，不属于任何一个镜头，应作为独立剪辑对象。
5. **`post_audio` 应拆成人声与音效两条链路**：不同岗位、不同工具、不同返工粒度。
6. **2026 年原生音画已可用，但正式系列剧仍应分轨**：原生音画只作为 `native_av_draft` 快速看表演和节奏，正式生产走 `separate_stems`，保证任何一句可单独返工。
